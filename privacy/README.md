# ZK Shielded Pool (Veil-inspired) — ETH mainnet

A fixed-denomination privacy pool for native ETH. You deposit `denomination` ETH
against a secret note commitment; later you withdraw to **any** address by
proving, in zero knowledge, that you own an un-spent note in the pool — without
revealing which deposit was yours. A per-note nullifier prevents double spends.

This is the Tornado-style design with **Poseidon** hashing (cheaper than MiMC,
same family Veil uses) plus an optional **compliance gate** so only screened
addresses can deposit (Privacy-Pools / 0xbow style).

> ⚠️ **Privacy = anonymity set, not the proof.** The chain is public: every
> deposit and withdrawal is visible. The ZK proof only hides *which* deposit maps
> to *which* withdrawal. With one depositor the link is trivial. Privacy grows
> with the number of deposits sharing your denomination — so use a fresh
> recipient address and wait for the set to grow before withdrawing.

> ⚠️ **Not audited. Dev trusted setup.** The Phase-2 zkey here is from a
> single-party dev contribution. A real deployment needs a fresh multi-party
> ceremony and a professional audit. Privacy mixers also carry real regulatory
> weight on mainnet (see Tornado Cash / OFAC) — the compliance gate is there for
> a reason; understand your jurisdiction before deploying.

## How it works

```
deposit:   commitment = Poseidon(nullifier, secret)         (secret stays with you)
           pool stores commitment as a Merkle leaf, holds your ETH

withdraw:  prove in ZK:  "I know (nullifier, secret) whose commitment is a leaf
                          under this recent root"  +  reveal Poseidon(nullifier)
           contract checks the Groth16 proof, marks the nullifier spent,
           sends denomination - fee to a fresh recipient
```

Recipient / relayer / fee are bound into the proof, so a valid proof can't be
front-run or re-targeted. A relayer can submit the withdraw tx and take `fee`,
so the recipient never needs gas (no link from a gas-funding tx).

## Components

| File | Purpose |
| --- | --- |
| `circuits/withdraw.circom` | Membership + nullifier circuit (6 public signals) |
| `circuits/merkleTree.circom` | Poseidon Merkle inclusion proof |
| `src/Verifier.sol` | Groth16 verifier (generated by snarkjs) |
| `src/MerkleTreeWithHistory.sol` | On-chain incremental Poseidon tree + root history |
| `src/ShieldedPool.sol` | deposit / withdraw / nullifiers / compliance hook |
| `src/AllowlistGate.sol` | Reference `IComplianceGate` (owner allowlist) |
| `src/interfaces/*` | `IHasher`, `IVerifier`, `IComplianceGate` |
| `js/build-circuit.sh` | Compile circuit + Groth16 setup + export verifier |
| `js/build-fixture.js` | Generate Poseidon bytecode, tree zeros, a real proof fixture |
| `js/lib.js` | Poseidon + JS mirror of the on-chain tree (proving reference) |
| `test/ShieldedPool.t.sol` | End-to-end test against a **real** proof |
| `script/Deploy.s.sol` | Deploy hasher + verifier + gate + pool |

## Build & test

```bash
cd privacy

# 1. JS deps (snarkjs, circomlib, circomlibjs, ethers)
cd js && npm install && cd ..

# 2. compile circuit + trusted setup + export Verifier.sol  (needs circom + snarkjs)
./js/build-circuit.sh

# 3. generate the on-chain Poseidon bytecode, tree zeros, and a proof fixture
node js/build-fixture.js

# 4. run the Solidity tests (real Groth16 proof verified on-chain)
forge test -vv
```

`build/` (ptau, zkey, wasm, fixture, Poseidon bytecode) and `js/node_modules/`
are git-ignored — they're regenerated by the steps above. `src/Verifier.sol` is
checked in because it's a source contract.

## Deploy

```bash
export PRIVATE_KEY=0x...
export MAINNET_RPC_URL=https://...
export DENOMINATION=1000000000000000000   # 1 ETH (optional)
export LEVELS=20                            # must match the circuit (optional)
export ENABLE_GATE=true                     # screen deposits (optional)

forge script script/Deploy.s.sol --rpc-url mainnet --broadcast
```

Run several pools at clean denominations (e.g. 0.1 / 1 / 10 ETH) rather than one
arbitrary-amount pool — uniform amounts keep the anonymity set from fragmenting.

## What's intentionally left for later

- **Arbitrary-amount UTXO notes + transfers** (full Veil model). This MVP is
  fixed-denomination on purpose — it gives the strongest per-pool anonymity and
  is far easier to get correct.
- **Relayer service + frontend** (note generation, encrypted backup, proof gen in
  the browser). `js/lib.js` is the proving reference to build these on.
- **Real association-set provider** in place of the demo `AllowlistGate`.
- **Multi-party Phase-2 ceremony** and an audit before any mainnet funds.
